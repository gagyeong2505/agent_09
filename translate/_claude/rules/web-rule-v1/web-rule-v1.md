# 웹 개발 규칙 (v1)

이 규칙은 이 프로젝트에서 웹 페이지 코드를 작성하거나 수정할 때 항상 적용되며, `developer` sub agent의 모든 작업도 포함합니다. 기술 스택, 파일 구조, 라이브러리 처리, 배포 방식을 정합니다.

## 1. 기술 스택과 파일 구조

- 순수 **HTML / CSS / JavaScript**만 사용합니다. 프레임워크, 번들러, 빌드 단계는 쓰지 않습니다(React, Vue, Tailwind 빌드, Vite 등 사용 안 함).
- 모든 작업은 `output/web/<작업명>/`에 두며 기본 구조는 다음과 같습니다:

```
output/web/<작업명>/
├── index.html          # 시작 페이지 (추가 페이지는 같은 위치에 <이름>.html)
├── css/
│   └── style.css       # 메인 스타일시트 (커질 때만 파일 분리)
├── js/
│   └── main.js         # 메인 스크립트
├── img/                # 페이지에 쓰는 이미지 (+ 확인용 캡처는 img/screenshots/)
└── lib/                # 내려받은 외부 라이브러리 (사용할 때만), 라이브러리별 폴더
    └── <라이브러리>/
```

- 상대 경로만 사용합니다(`css/style.css`, `img/hero.jpg`). 그래야 로컬과 GitHub Pages의 `/<작업명>/` 경로 양쪽에서 동작합니다.
- CSS는 `<head>`에서 불러오고, JS는 `<body>` 끝이나 `defer`로 불러옵니다. `lib/` 파일은 `js/main.js`보다 먼저 불러옵니다.

## 2. 코딩 기준

- **HTML**: 시맨틱 태그(`header`, `nav`, `main`, `section`, `article`, `footer`), 페이지당 `h1` 하나, 논리적인 제목 순서, 한국어 콘텐츠는 `lang="ko"`, `<meta charset="UTF-8">`와 viewport 메타 태그, `<title>`과 meta description.
- **CSS**:
  - 색상, 글꼴, 여백, 브레이크포인트는 레퍼런스 분석(`references/web/<작업명>/`)을 바탕으로 `:root`의 CSS 변수로 정의합니다.
  - 모바일 우선: 기본 스타일은 모바일용으로, 그다음 `min-width` 미디어 쿼리(예: 768px, 1024px, 1280px).
  - 레이아웃은 Flexbox/Grid를 쓰고, 가로 스크롤을 만드는 고정 px 너비는 쓰지 않습니다.
  - 웹 폰트: Google Fonts 또는 작업 폴더에 저장한 폰트 파일.
- **JS**:
  - 바닐라 JS, `const`/`let` 사용, 전역 오염 금지(모듈 패턴 또는 `type="module"`).
  - 요소를 찾기 전에 DOM 로드를 기다립니다(`defer` 또는 `DOMContentLoaded`).
  - 최종 결과에 콘솔 오류나 경고가 없어야 합니다.
- **접근성**: 의미 있는 모든 이미지에 `alt` 텍스트, 충분한 색 대비, 보이는 포커스 상태, 키보드로 쓸 수 있는 메뉴와 버튼, `prefers-reduced-motion` 존중(애니메이션 끄기 또는 줄이기).
- **콘텐츠**: 자료조사/레퍼런스 파일의 실제 내용을 씁니다. 사실이나 수치를 지어내지 않고, 빠진 내용은 명확한 플레이스홀더로 표시하고 보고서에 적습니다.
- **이미지**: 프로젝트에서 쓸 수 있는 이미지(직접 만든 것, 생성한 것, 무료 라이선스)만 씁니다. `references/web/`의 레퍼런스 스크린샷은 페이지에 절대 쓰지 않습니다.

## 3. 애니메이션 라이브러리

- 애니메이션이나 인터랙션에 라이브러리가 필요하면(예: GSAP, AOS, Swiper, Lenis, Lottie) 사용자에게 묻지 않고 직접 골라 설치합니다. CSS나 바닐라 JS로 충분하면 그것을 우선하고, 확실히 도움이 될 때만 라이브러리를 추가합니다.
- **CDN 링크가 아니라 내려받아서 설치합니다**:
  1. 프로젝트 밖의 임시 폴더(예: 세션 scratchpad)에 npm으로 설치합니다: `npm install <패키지>@<버전> --prefix <임시폴더>`.
  2. 페이지에 필요한 파일(압축된 JS/CSS, 필요한 에셋)과 라이선스 파일만 `output/web/<작업명>/lib/<패키지>/`로 복사합니다.
  3. 작업 폴더나 프로젝트 루트에 `node_modules/`, `package.json`, `package-lock.json`을 남기지 않습니다.
- 정확한 버전을 고정하고 기록합니다.
- 라이브러리 라이선스가 사용과 재배포를 허용하는지 확인합니다(MIT, Apache, BSD, GSAP 표준 라이선스 등).
- 설치한 라이브러리는 **반드시 모두 사용자에게 보고합니다**: 이름, 버전, 라이선스, `lib/`에 복사한 파일, 사용 목적(어느 섹션/효과).

## 4. 배포 (GitHub Pages)

사용자가 **확인 없이 배포하는 것**을 승인했습니다. 페이지가 5장의 점검을 통과하면 바로 배포합니다.

- **레포지터리**: 작업마다 별도의 GitHub 레포지터리를 만들며, 이름은 정확히 `<작업명>`(예: `suneung_2027`), 공개(무료 GitHub Pages에 필요), `gh`에 로그인된 계정 아래에 둡니다(`gh api user --jq .login`).
  - 같은 이름의 레포가 이미 있고 같은 작업의 것이면 업데이트(재배포)합니다. 다른 것이면 덮어쓰지 말고 멈춘 뒤 메인 세션에 묻습니다.
- **프로젝트 레포를 깨끗하게 유지**: `output/web/<작업명>/` 안에서 `git init`을 절대 실행하지 않습니다(중첩된 `.git`은 `agent_09` 레포를 망가뜨립니다). 프로젝트 밖의 임시 복사본에서 배포합니다:
  1. `output/web/<작업명>/`의 내용(`img/screenshots/` 제외)을 임시 폴더(예: 세션 scratchpad)로 복사합니다.
  2. 그곳에 빈 `.nojekyll` 파일을 추가합니다.
  3. 첫 배포: `git init -b main`, 커밋, 그다음 `gh repo create <작업명> --public --source . --push`.
     재배포: `gh repo clone <owner>/<작업명>`으로 임시 폴더에 받고, 파일을 새 복사본으로 바꾼 뒤 커밋하고 push합니다.
  4. `main` / 루트로 Pages를 켭니다(첫 배포에만):
     `gh api -X POST repos/<owner>/<작업명>/pages -f "source[branch]=main" -f "source[path]=/"`
  5. 빌드를 기다린 뒤(`gh api repos/<owner>/<작업명>/pages/builds/latest` → `built`), 사이트 URL이 HTTP 200을 반환하는지 확인하고 Playwright MCP로 열어 CSS, JS, 이미지, `lib/` 파일이 로드되는지 확인합니다.
- 커밋 메시지: 변경 내용을 짧게 한국어 또는 영어로 요약합니다.
- **사용자에게 전달할 결과**: 클릭 가능한 링크 형태의 배포 URL — `https://<owner>.github.io/<작업명>/` — 과 레포지터리 URL.

## 5. 배포 전 점검

- 페이지를 로컬에서 열어 Playwright MCP로 확인합니다(`browser-rule-v1` 준수):
  - 데스크톱(1440px)과 모바일(390px) 너비
  - 콘솔 오류 없음, CSS/JS/이미지/라이브러리 404 없음
  - 텍스트 넘침, 요소 겹침, 가로 스크롤 없음
  - 애니메이션이 동작하고, `prefers-reduced-motion`에서는 줄어듦
- 확인용 스크린샷은 `output/web/<작업명>/img/screenshots/`에 저장합니다(배포하지 않음).
- 모든 문제를 고치고 다시 확인한 뒤 배포합니다. 배포 후 실제 URL에서 간단히 다시 확인합니다.

3. 어떤 레퍼런스가 어느 섹션에 반영됐는지

5. **레포지터리 URL**과 **배포 URL(링크)**
6. 플레이스홀더나 사용자가 검토할 사항
